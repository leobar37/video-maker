# P-101 (R-1) · Proyección PortalProject, pestaña admin y material con proyecto

## Task Anchor
Objetivo del usuario: «Solicitar videos de un proyecto» (aprobado por el operador, 2026-10-05). Alcance autorizado de esta unidad al abrir gates: Proyección PortalProject, pestaña admin y material con proyecto. Éxito observable: Proyectos y material-atribuido pasan tests de unicidad/autorización/atribución y de uploads libres intactos; typecheck/build exit 0.

## Context
El portal v1 no conoce proyectos de Studio por cliente. Esta unidad crea la proyección canónica PortalProject (como PortalClient para clientes), la pestaña Proyectos en admin y la atribución opcional de proyecto al material de miembros logueados, sin tocar uploads libres.

Referencias normativas: `../contracts.md` (§1, §2, §5, §7), `../requirements.md`, `../context.md`, `../goal.md`. Es un plan ADITIVO sobre portal v1: sin catálogo público al cliente, sin escribir Studio, sin migración destructiva; la atribución es opcional y NULL = flujo v1 intacto.

## Outcome / Change
Migración `0003_portal_projects.sql`: tabla `portal_project` (id opaco, portal_client_id FK, studio_project_id, display_title sanitizado, projection_version, created_ms, UNIQUE (portal_client_id, studio_project_id)) y columna NULLABLE `material.portal_project_id`. Servicio `src/server/projects.ts`: alta/lista/renombre con `authorizeClient`/`requireAdmin` v1, `requireStudioId`, 409 por duplicado, auditoría `project.created`. API aditiva §5: `GET|POST /api/v1/clients/:clientId/projects`, `PATCH /api/v1/projects/:projectId`. SDK `packages/customer-assets/src/contracts.ts` + `src/api/client.ts`: tipos y queries aditivos. UI admin: `routes/_app.admin.clients.$clientId.projects.tsx` con cards por proyecto (estado placeholder de requests: sin datos hasta R-2, sin fabricar UI muerta). Miembro logueado: al iniciar upload puede enviar `portalProjectId` opcional validado contra su cliente; el pipeline `initUploadSession/completeUploadSession` acepta el campo opcional y lo persiste; uploads sin el campo quedan byte-a-byte iguales a v1 (probar con las suites existentes verdes). Nada de requests/tokens en esta fase.
