# P-103 (R-3) · CLI portal-request-pull, cierre/expiración y auditoría

## Task Anchor
Objetivo del usuario: «Solicitar videos de un proyecto» — la CLI importa lo cumplido al proyecto exacto (aprobado por el operador, 2026-10-05). Alcance autorizado de esta unidad al abrir gates: CLI portal-request-pull, cierre/expiración y auditoría. Éxito observable: CLI JSON y pull al proyecto exacto pasan pruebas de dry-run sin red, import verificable/idempotente, cierre/expiración y auditoría; portal:verify extendido con el recorrido request completo y negativas; build exit 0.

## Context
El request cumple pero nadie lo importa a Studio ni lo cierra con garantías. Esta unidad añade los specs portal-request-* (create/list/close/pull), importa al proyecto exacto por el bridge existente con SHA y procedencia, y cierra el recorrido offline con verifier extendido.

Referencias normativas: `../contracts.md` (§4, §5, §6, §8), `../requirements.md`, `../context.md`, `../goal.md`. Convención CLI v1: plan sin `--execute` (cero red/credencial), `--json` sin secretos, exit 0/1/2, credencial inyectada, origen explícito. Studio permanece canónico: import por servicios existentes, sin manifests remotos ni snapshots al portal.

## Outcome / Change
Specs en `packages/cli/src/specs/portal.ts` + `packages/cli/src/portal/requests.ts`: `portal-request-create` (valida gramática de límites/expiry localmente; con `--execute` devuelve `{requestId, url, expiresAt, limits}` para entrega manual; sin ella plan puro), `portal-request-list` (filtros --project/--state), `portal-request-close` y `portal-request-pull <requestId> --workspace <dir> --origin <url> --execute --json`: resuelve el PortalProject → proyecto Studio EXACTO del pointer (debe existir en el workspace; si falta, error claro sin inventar destino), reutiliza el bridge de `portal-material-pull` (descarga a temporal confinado, verifica SHA-256, registra input + procedencia `(origin, materialId, requestId)` en el asset abierto), idempotente por `(origin, materialId)`: reintento no duplica inputs ni entidades ni toca revisiones selladas. Exige `requests:read` + `materials:read` server-side. Cierre/expiración: `portal-request-close` y semántica lazy de R-2 ejercitadas end-to-end (expired una vez, close por admin con reason auditada). Verifier offline `scripts/customer-assets-verify.ts` EXTENDIDO con etapa de requests: admin crea proyecto+request+link → invitado sube hasta límite → auto-close → CLI pull al proyecto exacto con verificación SHA/procedencia → negativas (token de otro request, request cerrado/vencido, exceso de cuota, guest sin catálogo, pull a proyecto inexistente). Auditoría §8 completa y sin token/URL en evidencia.
